# Research peer guide

Start the frontend and API with `npm run dev`, then open the local app. A backend is needed for scientific experiments, CSI examples and generated PDF reports. Browser QR/editor/local saves work without it. Ten workspace themes remain in Settings. Create an account and sign in for cloud operations after installing the Phase 3 migrations; confirm your email if required by the project’s Auth settings.

## Networks and revisions

The folder icon opens **Research workspace**. My Projects lists your owned networks; Shared With Me includes direct/team access; Recent Projects is this browser's opened-project list; stars sync for signed-in users; archived networks have a separate view. Search names and choose newest/oldest/name sort. Duplicate makes a fresh project ID without copying ownership/version metadata. Imports validate schema/size; export full JSON as a portable backup. The first dashboard index loads up to 200 accessible rows/table (newest for networks/runs/templates); this is a documented limit, not an unlimited catalog search.

Details opens saved revisions, rename, template creation, current owner and role. Restore creates a new version; it does not change previous experiments. A version conflict never silently overwrites a peer's work: reload the cloud version (save/export local edits first) or **Save current as copy**. Autosave pauses while workspace/laboratory dialogs are open; explicit Save current and Run save the chosen configuration. Projects with jobs/history cannot be hard-deleted through the app; archive them. Local-only projects have no cloud revision history until saved while signed in.

## Collaboration

Project owners can grant viewer/editor access using a peer's UUID from Profile → Account ID. Teams have an owner and viewer/editor members; assign your project to a team you own. The owner may remove grants later. Editors save revisions and run studies; viewers read/compare/export. Viewers can duplicate an accessible configuration into their own independent project. No automatic invitation email or live concurrent editor is supplied.

Create a seven-day authenticated invitation from Details. Tokens are unguessable, stored hashed, and put in the URL fragment. Share the copied URL yourself. Recipients sign in and click Accept invitation. Every invitation kind grants access to the **whole project/history**, including when the selected target is a report, template or saved configuration. Use a separate project if only a subset should be shared. Revoking a token blocks future acceptance; remove existing direct/team memberships separately. Copies already downloaded remain accessible to their holders.

## Experiments and comparison

Laboratory preserves all Phase 2 models, controls and algorithms. Run saves a frozen input snapshot, starts a new job and reconnects after refresh. Production requests use persistent idempotency keys across lost-response retries. User-visible failed/cancelled/interrupted states never imply a successful fix. The compute model remains 0.2.0 so historical results retain their meaning.

Recent Experiments combines local terminal snapshots and authorized cloud jobs/runs. Select two checkboxes for a nested configuration diff, including per-object mobility, environment, seed and estimators. Open results restores the saved network and recorded overlay. Rerun configuration creates a fresh network copy; executing it creates another run rather than changing history. Queued/failed jobs without a published artifact retain status/errors but cannot fabricate downloads. Use the Laboratory active job panel for polling/cancellation; metadata is also available through the authenticated API.

## Scientific exports

From a terminal Laboratory result or a recorded scientific Share preview, open **Publication exports**. Set figure title, axes/units, legend and dimensions. The CDF pools sweep/trial/location samples per estimator; failure counts remain explicit. Labels alter presentation, not data or units. SVG is vector output; PNG is rendered at 2× dimensions. CSV/JSON contain actual attempted epochs/failures. The reproducibility manifest includes the exact configuration, seed, scientific version, metrics, environment when recorded and a deterministic configuration hash.

PDF is generated by Python with real summary metrics, anchor layout/sampled trajectories, sampled CDF, method assumptions, parameter units, limitations and exact configuration. It is not a screenshot presented as a new study. Display traces are sampled to at most 2,000 records; full-data SVG and complete JSON remain available. Save a generated file to cloud artifact history optionally (published cloud run/sign-in required, ≤2 MB/file); full large experiment JSON is already persisted as worker chunks. Derived artifacts cannot overwrite the original run. Custom non-Latin glyph coverage in the bundled PDF font is limited; verify your publication labels.

## Advanced signal example

**CSI lab** is separate from positioning. Configure path delays/complex gains, bands/spacing/bandwidth, snapshots, SNR and calibration error. Run the conventional matched/weighted scans first; inspect their sidelobes. MUSIC/ESPRIT are marked experimental with explicit assumptions and rejection cases. A scan peak is not a guaranteed earliest/LOS path, and full Kazaz MBWDE is not implemented. Export the actual CSI/result JSON for reproducibility. See ADVANCED_SIGNALS.md before using these demonstrations in research claims.

Local browser files/IndexedDB are caches owned by this device/browser profile, not a confidentiality boundary between people sharing the same unlocked browser. Use separate profiles for research accounts, export backups and clear sensitive local data before sharing a device. Server reads and exports still enforce current project authorization through RLS.

## Optional 3D inspection and editing

The studio starts in 2D. Select 3D beside the workspace breadcrumb to inspect the same network. Orbit with the primary pointer, pan with the secondary pointer, and zoom with the wheel or touch controls. Use the camera menu for perspective/orthographic projection and the Top/Front/Side/Fit/Reset buttons for inspection. Collapse the simulation panel for more room on short screens.

Select an object in the scene or tree. While paused at t=0, translate its initial pose with the gizmo or the Properties inspector. XY movement uses the selected snapping interval. Waypoint motion follows the path: translate its points to move the route. Add objects at the origin using Add object, then place them with the inspector. Duplicate, delete and undo/redo use the same project history. Cloud viewers can inspect the 3D scene but cannot edit it.

View and layers controls affect only presentation. Receiver altitude is metadata; obstacle extrusion is illustrative. Scientific estimates, links and the recorded XY uncertainty ellipse remain planar. No vertical position estimate is produced. Open Recorded scientific data to inspect the selected stored epoch and its link values/residuals. A changed network must be restored from the snapshot before its overlay is shown.

If WebGL is unavailable or the graphics context is lost, choose Return to 2D. Your project is preserved. Camera/view changes are not scientific edits. See docs/3d/COORDINATE_MODEL.md for the vertical limits.

## Phase 5 usability and research workflows

- Use **Rename** beside the project name in Studio, or in dashboard Details. Studio edits stay in the draft until saved; names use 1–80 characters.
- The dashboard follows all ten palettes. Hover or keyboard-focus the major run actions for explanations; laboratory numeric fields include units, defaults and parameter effects.
- Inspector → Simulation exposes baseline duration up to 60 minutes, with presets. Laboratory has a separate trajectory duration up to five minutes. The planned-work message explains existing budgets; reduce trials/sweeps or increase the sample interval for long experiments.
- For buildings and walls, **Width (X)** and **Depth (Y)** define the original footprint. Explicitly set **Height (Z)** and optionally **Base elevation (Z)** for per-object 3D geometry. Defaults chosen through these actions are assumptions until entered/confirmed by you. Clearing a dimension makes it unknown. Unknown base is shown relative to the presentation ground. This opts the editable project into format 2; old clients cannot open it. Vertical dimensions do not change horizontal obstruction or the approved solver.
- Workspace filters act on the loaded index, currently capped at 200 rows per category. Details show recorded editor/revision, configuration and recent runs. Sharing previews explain full-project/history access. Direct and team permissions compose.
- On a stale cloud save, compare the preserved draft with the latest revision, export/copy it or explicitly reapply selected object/settings blocks. Object matching uses IDs; this is a two-way comparison, not live editing or an automatic three-way merge.
- Recent Experiments lets you select two to four immutable runs. Compare full-data recorded metrics, scientific configuration differences, CDFs/residual distributions and a selected XY trajectory cohort. Watch seed/model/dataset warnings; changes across several variables do not isolate a cause.
- Export complete comparison JSON, summary CSV, chart SVG/PNG, manifest and printable report. Use the printable report's Print / Save PDF control; native per-run PDF remains available in Publication exports. Named report collections are browser-local run references; export source JSON alongside references when sharing.
- Imported experiment snapshots are labelled locally and retain their original data. Import labels are provenance notes, not attestation.
- 3D **Saved view presets** retain canonical camera preset/projection, units and layers separately from projects. Free-orbit camera pose is not saved. View presets are browser-local and never change scientific configurations.
- Recorded collaboration activity begins when server logging is installed. It is a history feed with actor/time/resource references, not real-time notifications or a backfilled audit of earlier work. Offline report generation cannot be observed by the server; uploaded derivatives are labelled artifact-recorded events.

## Collaboration center

Open **Collaboration** from the main navigation. In **People**, save an optional unique username and discovery preferences; find peers using an exact username or permitted verified email. To offer a studio, create a workspace in **Manage access**, designate it in your peer profile, and explicitly assign projects to it. Studio membership includes only those assigned projects.

Use **Request studio access**, choose Viewer or Editor, review the recipient/scope and send. The owner reviews it in **Requests & Invitations** and explicitly accepts (confirming the approved role) or rejects it; requesters may withdraw pending items. Pending items grant nothing.

Use **Invite people** to select an owned studio, team or project, find/add eligible peers, choose a role and review before sending. These are in-app offers; no email is sent. Recipients accept or reject them in Collaboration. Offers expire after seven days; owners can revoke or renew them. Existing invitation links can also be accepted there.

**Shared with me** lists only currently accessible resources and their effective roles. **Manage access** shows direct and inherited membership, role changes, removal, pending items and reusable project/research links. Removing one grant may leave independent team access. Revoke invitation links separately; previously downloaded copies cannot be recalled. Notifications and their read state are in **Overview**. See [Collaboration documentation](collaboration/OVERVIEW.md).

## Project library and blank projects

**Home** shows the research dashboard. **Projects** opens the project library and clears earlier search/filter selections so your projects are visible. Use **New Project** for a blank canvas with no transmitters, receivers, obstacles or trajectories, or select a starter in **Starting network**. The new project keeps your workspace theme. Add your own objects using the studio tools.


## Panel visibility, range model and signup

On desktop, use the panel icon beside **Network objects** to collapse the entire object list and project-reference panel. The remaining rail expands it again. Your preference is remembered in this browser; it does not change objects, selection or undo history. Press **/** to expand the panel and focus object search. Compact mobile layouts retain their existing automatic panel hiding.

The inspector’s **Simulation → Measurement model** explains the calibrated baseline and every symbol: rᵢ is simulated range in metres, p is the receiver’s unknown 2D position, aᵢ is transmitter i’s known 2D position, ‖p − aᵢ‖ is horizontal Euclidean distance, and εᵢ is independent zero-mean Gaussian range error with the configured standard deviation and seed. The model isolates geometry and range noise for repeatable solver comparisons. Advanced propagation and clock effects belong to Scientific laboratory. Delete actions use readable red in every theme, including the monochrome themes.

Signup follows the hosted Auth settings. If signup returns a session, the account dialog reports that you are signed in. Otherwise it asks you to check email when confirmation is required. Email-send quotas apply to the entire project, not individual addresses; the dialog explains this and pauses repeated signup attempts for a minimum of 60 seconds while leaving existing-account sign-in available. That pause is not a promise that the server quota has reset. Public signup with email ownership verification requires a configured SMTP sender; see Supabase’s [email delivery documentation](https://supabase.com/docs/guides/auth/auth-smtp).

On 21 October 2026 the project owner explicitly approved disabling email confirmation on the hosted Terra-Lab main project for development/testing. New signup therefore does not require sending a confirmation email. This setting does not prove ownership of an email address. Re-enable confirmation and configure SMTP before relying on verified email identities.
