## Architecture and authority

Browser AI Studio → same-origin authenticated Next routes → strict tool schemas → fresh project/RLS/role checks → signed, actor/project/revision-bound review → existing domain save or scientific queue → actual status/results/export. The model proposes actions; it cannot approve them. Six model steps, twelve tools, bounded context/results, sixty operations/user/minute and at most two concurrent inference requests/user (sixteen/server process) constrain work. Admission/rate maps are process-local; distributed enforcement remains a deployment requirement.

The twenty-tool catalogue has fifteen general domain tools and five additional local testing tools. Tests are advertised and accepted only for the explicitly enabled loopback development operator. Hosted production refuses testing even if its flag is set. There is no shell string, arbitrary argv, package installation, code patch, filesystem, SQL, generic HTTP or browser tool for the model.

The separate Python test helper is necessary because the existing scientific queue accepts numerical jobs, not repository commands. It is not another scientific queue. It discovers a fixed repository, fingerprints the actual source, takes a disposable snapshot and launches exactly one of eleven operator-defined commands. Installed dependencies are shared; workspace packages resolve to copied source. The reviewed SHA-256 must still match. Results preserve actual times, exit code, bounded redacted output and counts only when a real summary supplies them. Unknown counts remain null. Missing exit status, timeout, interruption, cancellation and nonzero exit are never reported as passes.

The available Windows fallback is explicitly for **trusted local development**. Windows Job Objects impose a 30% CPU hard cap, 48 processes, 3 GiB/process and 6 GiB/job committed memory, with command deadlines of 120–420 seconds and a 64 KB output cap. Failure to install limits fails execution. A clean environment removes provider/database/deployment credentials; Node/Python network guards deny external connections and allow loopback only where declared. These guards, shared dependencies and ordinary filesystem access are **not an adversarial OS sandbox**. Untrusted repositories and shared hosting require an independently provisioned sandbox before test execution can be enabled.
